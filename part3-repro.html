1三種「對上」

先說這一頁在對什麼。fly-blackjack 是一個人（本頁叫他作者）放在 GitHub 上公開的一包程式（repo：那個公開的程式資料夾；README：資料夾裡作者寫的說明與結果摘要），它拿果蠅腦的接線資料去學打 21 點（是什麼、怎麼學，見 PART 1）。本頁把那包程式裡 21 點這個實驗在自己的電腦上（本機）重跑一次，分三步，每一步把跑出來的數字對回作者寫的數字。

重現的每一步都要先回答：本機的數字要和作者的差多少以內，才算對上？答案取決於那一步有沒有隨機性、隨機性有沒有被固定住。重現型的專題一律用三種判定標準：

判定標準什麼時候用本頁哪些步驟（BJ1 到 BJ3 是下面三個步驟的代號，本課自己編的）
逐位相同：檔案一個位元都不差；數字則到作者給出的位數為止每一位都相同這一步沒有隨機性，或隨機性由亂數種子完全固定（種子 seed 是給電腦隨機數產生器的起點；起點相同，抽出來的整串隨機數就相同，所以「隨機」的過程也能重做得一模一樣）BJ1 切出的蕈狀體（檔案指紋、細胞數、連結數）；BJ3 把作者附的大腦檔重新評分（評分沒有隨機性）
在誤差範圍內：與作者的值相差不超過一個事先訂好的比例這一步的隨機輸入在不同電腦上不保證相同本課沒有用到：21 點的發牌與探索都固定了種子
形狀相同：條件之間的高低順序與差距方向一樣數字本來就不會一樣，或作者只給了取整的數字BJ2 的成績：作者只給整數百分比，而且本機三個種子彼此就差好幾個百分點
白話：擲一顆骰子一百次，只要兩個人用同一顆「固定好的」骰子，結果會一模一樣（逐位相同）；用兩顆不同的骰子，各擲一百次，平均點數都會接近 3.5，但不會剛好一樣（誤差範圍）；如果比的是「灌鉛的骰子平均點數比正常的高」，換另一批骰子重做，兩個平均數字都會變，但灌鉛那顆仍然比較高（形狀相同）。判定標準要在跑之前訂，跑完才訂，就變成看結果決定標準。

BJ2 的兩個數字事先怎麼訂。成績（作者叫它勝率，其實是平均每手的淨輸贏，第 4 節）：作者只在程式註解裡給了取整數的百分比，所以比的是「完整模型升到作者寫的水準、對照組不動」，形狀相同。一致率（模型在基本策略表 260 格裡選對幾格的比例，第 5 節）：README 只給整數的 52%，事先訂比到整數位。作者表格裡的「連結體 ＋ 多巴胺」就是完整模型，本頁文字一律叫它完整模型。

骰子是說明用的例子，不是實驗數字。

2結論：三個步驟的成績

步驟做什麼判定標準結果
BJ1下載資料、切出蕈狀體（果蠅腦裡負責學氣味好壞的一小塊，第 3 節），跑兩次、比 md5（檔案指紋，內容一樣指紋才一樣）細胞數、連結數與 README 相同；兩次 md5 相同細胞數相同、md5 相同；README 寫的兩個連結數與作者 repo 裡的檔案不一致（文件錯誤，不影響結果）
BJ221 點 30,000 手，四個條件各 3 個種子成績形狀相同：完整模型升到約 −16%、對照組不動形狀相同（完整模型 −14.8%，對照組都在 −47% 左右）
BJ3把作者附的、打過 30,000 手的大腦檔載入作者的程式重新評分與基本策略（一張公開的「每種牌面該怎麼打」的表，PART 1 第 5 節）的一致率比到整數位：README 說 52%對不上：作者自己的三份資料是 52%、48.1%、53.1%，重新評分是 51.9%，本機重跑是 45.3%

每一列的數字出處見下面對應的小節。表裡兩處對不上：BJ1 那一處是作者文件的錯，不影響任何結果；BJ3 那一處影響結果，是這一頁的主要發現。

BJ1–BJ3 是本課自己編的代號。下載包是 PART 2 教你抓下來的本課程式資料夾，裡面的 blackjack/run_all.sh 照這個順序執行，每一步的終端輸出存在 logs/、數字存在 results/；本課自己實跑的那一份 logs 與 results 收在課程網站程式倉庫的 out/ 資料夾，本頁寫「出自 out/…」指的都是它，給想核對的人用。作者的 21 點程式沒有命令列入口（沒有一條可以直接在終端機打的指令；作者是在 Python 裡呼叫函式、或用他的網頁版跑的），下載包的 blackjack/scripts/ 補了兩支小程式去呼叫作者的函式（不改作者的程式）。

3BJ1　下載並切出蕈狀體：md5 相同，README 的兩個連結數對不上

先認識這一步的材料。連結體是整隻果蠅腦「哪顆神經元接到哪顆、幾個突觸」的完整表格；蕈狀體是其中負責學「這個氣味是好是壞」的一小塊，模型從它切出四群神經元：氣味輸入 PN → 把氣味編成代碼的 KC → 輸出 MBON，加上告訴它賞或罰的多巴胺神經元 DAN（PART 1 第 2 節）。BJ1 驗的是「切出蕈狀體」這一步能不能一模一樣地重做。作者的 flybrain.mb.fetch 從 connectome_data_prep（另一位研究者 Yijie Yin 在 GitHub 上公開的整理版，把 MaleCNS（一份公開的雄果蠅全腦連結體資料集的名字）連結體存成可以直接讀的表格）下載連結矩陣（哪顆神經元連到哪顆、幾個突觸），下載完核對檔案大小與筆數（PART 2 第 5 節）；flybrain.mb.extract 從裡面切出 PART 1 第 2 節表裡的四群神經元（PN、KC、MBON、DAN），存成一個檔 data/mb_circuit.npz。README 宣稱這個切法在任何電腦上都逐位相同（同一支程式跑兩次應得到相同的 md5），但作者沒有附上他自己算出的 md5 值。所以能驗的是兩層：第一層照作者說的跑兩次、比兩次是否相同；第二層把切出來的細胞數與連結數對回作者存進 repo 的紀錄檔。比檔案不必逐條比對幾萬條連結，比 md5 就夠了：md5 是從整個檔案算出來的一串指紋，內容只要差一個位元，指紋就完全不同。本課跑兩次、比兩次的 md5：

32dc49359f237250162ed33dcb5da93c  data/mb_circuit.npz
32dc49359f237250162ed33dcb5da93c  data/mb_circuit.npz

兩次相同（第一層過）。這只證明同一台電腦兩次一樣；跨電腦的證據在下一張表。輸出在 out/blackjack/logs/bj1_md5.txt。

再把切出來的細胞數與連結數對回作者的說法。下表三欄：README 寫的數字；作者執行程式後存進 repo 的紀錄檔 data/mb_manifest.json（程式切完會把細胞數與連結數記在這裡）；本機切出來的。

4BJ2　21 點 30,000 手：成績對上

21 點的規則、編碼、學習在 PART 1 第 5 節。模型怎麼打：每一手，把「自己的點數、手裡的 A 算不算 11 點（軟手）、莊家的明牌（莊家翻開的那張）」連同候選的動作一起編成一組像氣味一樣的 KC 活化——同一手牌配「要牌」（再拿一張）「停牌」（不拿了）「加倍」（加一注、只再拿一張）是三種不同的「氣味」，所以每個動作各有一個好惡值——選最高的；一手結束，贏了給獎賞多巴胺、輸了給懲罰多巴胺，這一手做過的每個決定都依 PART 1 第 4 節的學習規則更新連結。作者在 flybrain/mb/blackjack.py 的檔尾用註解寫了實驗設定：3 個種子、每個 30,000 手、對照組先跑。四個條件：未訓練（不學、不探索）、關掉學習、切斷多巴胺、連結體 ＋ 多巴胺（完整模型），各打 3 個種子；表在下面。勝率在這裡指平均每手的淨輸贏（以一注為單位、寫成百分比：−15% 就是平均每手輸 0.15 注），取最後 2,000 手。表裡列名的「探索」是模型每一手有一定比例不看好惡值、隨機亂選動作，這個比例從 35% 隨手數遞減到 3%。兩個對照組也照同樣的時程把亂選比例降下來，但它們的曲線沒有往上走：三個種子平均從第一個 2,000 手的 −42.7% 掉到最後的 −47.5%，掉了約 5 個百分點。掉的原因是亂選（−44.5%）其實比照沒學過的好惡值選（未訓練那組的 −48.0%）略好一點，亂選變少，成績就往下靠向未訓練的水準。所以「不動」指的是沒有上升、沒有離開「什麼都沒學」那一帶；而有多巴胺那組往上走了 10 個百分點，方向相反，這個上升不可能是亂選變少造成的。

未訓練−45%−44.8%／−46.9%／−52.3%−48.0%
關掉學習（探索照常遞減）−45% → −45%−43.9%／−47.0%／−51.5%−47.5%

上表本機欄只列最後 2,000 手；本機的「開始」值在頁尾的終端機輸出（winrate 箭頭前面那個數）。兩個「開始」量的不是同一個時間點：作者寫的 −45% 是還沒學之前的水準（和未訓練那列一樣）；本機的「開始」是打完頭 2,000 手的平均，而學習從第 1 手就開始，這 2,000 手已經在學，所以是 −26% 上下。本課不拿兩個「開始」互比，判定比的是最後的水準與形狀。作者的值出自 blackjack.py 檔尾註解（收在 out/upstream/blackjack_py_RESULT_comment.txt）；本機在 out/blackjack/bj2_blackjack_30000.json。「關掉學習」與「切斷多巴胺」三個種子的數字一模一樣：多巴胺送不到 MBON 時連結一樣不會變，兩種對照對模型的效果相同，又用同一串亂數抽牌與抽探索，打出來的每一手都一樣。本機三個種子彼此差到 7 個百分點，表示單一種子的勝率本來就有這麼大的浮動，所以這一步比的是三種子平均與形狀，不是逐位。

勝率的改善重現了，而且只出現在有多巴胺的那一組。不過圖 2 也看得出，學會的那條只爬到「永遠停牌」參考線附近——成績和一個永遠不要牌的玩家差不多。

5BJ3　作者附的大腦檔：學到的策略對不上

所以作者接著宣稱的「它學到什麼策略」才重要：看模型在基本策略表的 260 格裡每一格選的動作有幾格與表相同，就是一致率（表的定義見 PART 1 第 5 節）。作者還附了一個訓練完的蕈狀體狀態檔 data/brain_seed.json（下面叫它大腦檔）。這一部分，作者自己留下的三份資料就互相矛盾：

來源與基本策略一致260 格裡的選擇
README52%幾乎都停牌，只在 10、11 點要牌
blackjack.py 檔尾註解48.1%停牌約 227 格、加倍 0 格
作者附的大腦檔 data/brain_seed.json（檔內記錄，由作者網頁版的 JavaScript 評分程式算出；檔內標明來自「Python 30,000 手、種子 0」）53.1%—
同一個大腦檔，載入作者的 Python 模型重新評分51.9%要牌 97、停牌 149、加倍 14
本機重跑（同樣用種子 0）43.8%要牌 6、停牌 214、加倍 40

大腦檔的評分由 blackjack/scripts/bj3_author_brain.py 算出（out/blackjack/bj3_author_brain.json）；本機三個種子的平均一致率是 45.3%。還有一件事：沒學過的蕈狀體一致率就已經 45%（幾乎每格要牌，剛好對中表上該要牌的那些格），學完三個種子平均仍是 45.3%，一致率幾乎沒有因為學習而上升（頁尾輸出裡完整模型三個種子的 agree 從 0.41、0.39、0.47 升到 0.44、0.45、0.47，起點比未訓練的 45% 低，是因為頭 2,000 手還有三成多的動作是亂選的；比較基準是「未訓練 45%」對「學完 45.3%」，不是每行自己的起點）；所以 45% 到 53% 之間的差異能不能代表「學到策略」，本身就存疑，這比「對不上 52%」更重要。

先說表裡作者大腦檔的兩個值：同一個大腦檔，檔內記錄 53.1%（138 格）是作者網頁版自己算的，載入 Python 重算是 51.9%（135 格），兩套評分程式對同一份連結強度算出的格數差 3 格，原因本課沒有追。作者附的大腦一致率約 52%，和 README 相符，但它要牌 97 格，既不是 README 說的「幾乎都停牌」，也不是程式註解說的「停牌約 227 格」；大腦檔標明是種子 0，本機用同一份程式、同一個種子重跑，又是另一套結果。勝率能重現、策略卻不同，並不矛盾：學會的勝率只到「永遠停牌」那條線，很多張不同的 260 格表都能打出差不多的勝率，勝率對上不代表每一格的選擇相同。所以這一步的結論要分開講：「有多巴胺才會變好」可以重現；「學到什麼策略、一致率多少」從公開的程式碼重現不出來。最直接的解釋是附的大腦檔由另一個版本或另一組設定的程式產生，但作者沒有記錄，本課無法確認。PART 5 把種子 0 這 30,000 手錄成影片，可以親眼看它從「幾乎每格都要牌」變成「幾乎每格都停牌」。
