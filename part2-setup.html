1兩個指令

這一頁會一直用到幾個詞，先認識一次：

詞意思
終端機打字下指令的視窗（macOS 叫「終端機」，Linux 叫 Terminal）。本課所有指令都是貼進去按 Enter
套件別人寫好、可以直接拿來用的 Python 程式庫，例如 numpy（數值運算）、pandas（表格）
conda、環境conda 是管理「環境」的工具；一個環境就是一份獨立的 Python 加上它自己的套件，環境之間互不干擾。本課只建一個（第 4 節）
pip在一個環境裡安裝套件的工具；本課用 conda 建環境、用 pip 裝套件
repo、GitHubGitHub 是放程式碼的網站；一個 repo（repository）就是一個專案的全部檔案與它的修改歷史。commit 是其中一次存檔的編號（第 5 節）

下載 flyblackjack-code.zip（首頁〈需要什麼基礎〉那一格也有同一個連結），解壓縮到一個空資料夾，在那個資料夾裡開終端機。想先確認檔案完整，可以執行 sha256sum -c SHA256SUMS.txt（第 3 節）；然後依序執行：

bash setup_envs.sh              # 建一個 conda 環境（只需一次）
bash blackjack/run_all.sh       # BJ1–BJ5、加做檢查 X1–X4

指令裡的代號，各對應後面哪一頁的哪一步：

代號意思在哪一頁
BJ1–BJ5重現的五步：Dino、切出蕈狀體、制約學習、覓食、21 點PART 3
X1–X4作者沒做的四項檢查：加到 50 個種子、打亂哪一層接線、換 KC 選法、MBON 標記對文獻PART 4

本課在一台 Linux、12 核 CPU 的電腦上，從解壓縮開始實測：建環境 14 秒，run_all.sh 21 分 39 秒。建環境的秒數要打個折：它是在一台已經下載過所有套件的電腦上測的（先把原有的環境改名讓開、再從零建一次，套件直接從本機快取拿）。你的電腦若是第一次建，要把套件全部下載下來（裝好後約 515 MB），時間取決於網速，請預期比這久。

實測時間出自 out/porttest.json。這個檔和本頁其他引用的 out/… 都是本課實跑後存在課程網站 repo 裡的紀錄，給你對照用；不是你跑完會在自己電腦上長出來的檔案（你的結果在 results/，第 7 節）。

2需要什麼

項目說明
作業系統Linux 或 macOS。本課在 Linux 上跑；fly-blackjack 的每個實驗都固定了亂數種子（PART 3 第 1 節），照理在另一個系統上也會得到相同數字
condaAnaconda 或 Miniconda 都可以（Miniconda 比較小，只含 conda 本身，建議選它）；到官方網站下載安裝程式照步驟裝。裝好後在終端機打 conda --version，印出版本號就表示可以用
git、curlgit 從 GitHub 取得程式碼，curl 下載資料檔。多數 Linux 與 macOS 已內建；打 git --version、curl --version 看有沒有印出版本號，沒有就用系統的套件管理工具安裝
網路與硬碟跑完後下載的程式碼與資料共約 129 MB，環境約 515 MB
GPU不需要

3下載包裡有什麼

下載包只有本課自己寫的程式。被重現的 fly-blackjack 由 run_all.sh 從 GitHub 取得並切換到固定的版本；它是 MIT 授權（允許任何人複製、修改、散布），本課不附它的檔案只是為了讓你跑到的一定是 GitHub 上的那一份。

檔案做什麼
setup_envs.sh建一個 conda 環境，套件版本照本課實跑時固定
blackjack/run_all.sh取得 fly-blackjack、下載 MaleCNS 連結體整理好的連結矩陣（切蕈狀體的來源，PART 1 第 2 節），依序跑 BJ1–BJ5、X1–X4
blackjack/scripts/覓食與 21 點兩個實驗，作者的程式裡沒有可以直接從終端機執行的指令（沒有「命令列入口」，作者是在 Python 裡呼叫函式跑的），所以本課寫了幾支小程式去呼叫作者的函式，不改作者任何一行；X1–X4 也在這裡
check.py、expected.json驗收：逐項比對你跑出來的數字與本課實跑的結果（第 7 節）
SHA256SUMS.txt每個檔案的 SHA-256 指紋：由檔案內容算出來的一串 64 個字，內容改一個位元組就完全不同。執行 sha256sum -c SHA256SUMS.txt 會重算每個檔案的指紋並與這份清單比對，確認下載的檔案沒有損壞或被改過

repo 的版本與下載來源寫在下載包的 blackjack/run_all.sh。

4一個環境

fly-blackjack 只用三個套件，彼此沒有版本衝突，所以一個環境就夠。版本照本課實跑時固定——不是因為別的版本一定會出錯，而是重現的第一條規矩是把能固定的都固定，對不上時才知道差在哪裡。

環境名稱Python關鍵套件
flyplay_bj3.11numpy 2.4.6、scipy 1.17.1、pandas 3.0.6

5兩個要固定版本的地方

一、程式碼：固定到某一個 commit

GitHub 上的專案會一直更新，今天下載的和半年後下載的可能不是同一份程式。commit 是專案每一次存檔的版本編號（像 004b2e3 這樣一串字）；run_all.sh 取得程式碼之後會切到本課用的那一版。作者日後改了程式，你跑出來的仍然是本課的那一版。

二、資料：下載時核對大小與筆數

蕈狀體的連結矩陣不是從 MaleCNS 原始資料（1.2 GB）切的，而是從另一位研究者 Yijie Yin 公開的整理版 connectome_data_prep 下載兩個檔（約 107 MB）。作者的下載程式沒有固定那個 repo 的版本，取的是它當下的主分支；代替的做法是核對：下載完先比對兩個檔案的位元組數（78,770,675 與 28,023,979），載入時再核對神經元數、突觸數、各群細胞數都等於作者寫死在程式裡的值，有一項不同就停下來報錯。所以日後整理版若更新，BJ2 會在這裡停住，而不是悄悄算出不同的蕈狀體；到時要去 connectome_data_prep 找回舊版的那兩個檔。

檔案大小與核對項目出自作者的 flybrain/mb/fetch.py；BJ2 下載時印出的核對行收在 out/blackjack/logs/bj2_fetch.log（PART 3 第 4 節有節錄）。

6一個會讓結果悄悄改變的陷阱

如果你曾經用 pip install --user 裝過套件，它們會被放在家目錄（你的個人資料夾，終端機裡寫成 ~）的 ~/.local 底下（打 ls ~/.local/lib，有 python3.x 開頭的資料夾就表示有）；而 Python 預設會把這個資料夾也加進搜尋範圍——包括 conda 環境裡同一個版本的 Python。結果是：你以為在用環境裡固定好的 numpy 2.4.6，實際上載入的可能是 ~/.local 裡的另一個版本，而且不會有任何警告。

下載包的每一支腳本都先設定 PYTHONNOUSERSITE=1，讓 Python 不去讀 ~/.local。照第 1 節的兩個指令跑就不必管它。只有當你想自己單獨重跑某一步、或改個參數試試時（例如 21 點只跑 2,000 手、只用種子 0），才需要手動下指令，這時也要在前面加上它。下面這條就是例子，要在 blackjack/repo/ 裡執行；兩個數字依序是手數與種子：

PYTHONNOUSERSITE=1 PYTHONPATH=. $(conda info --base)/envs/flyplay_bj/bin/python ../scripts/bj5_blackjack.py 2000 0

$(conda info --base) 會自動換成 conda 安裝的位置，後面接的是 flyplay_bj 這個環境自己的 Python；直接指定環境裡的 Python 來執行，就不必先用 conda activate（切換到某個環境的常見指令）。PYTHONPATH=. 是讓 Python 在目前資料夾（作者的 repo）找得到 flybrain 這個套件。

numpy 2.4.6 是 flyplay_bj 環境固定的版本（out/blackjack/env.txt）。

7跑完之後怎麼看

run_all.sh 跑完會自動執行 check.py，逐項比對你的結果與本課實跑的結果，每一項印一行：

符號意思
✓對上了。check.py 比的對象是本課的實跑結果，不是作者的數字，所以每一項都可以要求逐位相同（對作者的三種判定標準見 PART 3 第 1 節）
✗對不上。後面會印出本次的值與預期的值。看到它先做兩件事：打開那一步的 logs/ 檔看最後幾行有沒有錯誤訊息（最常見是網路中斷、下載不完整）；然後重跑一次 run_all.sh。還是 ✗ 的話，對照第 5 節看是不是某個版本變了

本課的可攜測試（解到空資料夾、從建環境開始跑）最後一行是：

blackjack：19 項通過，0 項不符（共 19 項）

出自 out/porttest.json。開頭的 blackjack 是驗收表（expected.json）的分組名，這一包只有這一組。

想看某一步的細節，打開 blackjack/logs/（在你解壓縮的資料夾底下；results/ 也在同一層）：每一步一個檔案，是那一步的完整終端輸出，最後幾行通常就是結果表。所有數字另外以 JSON 存在 results/，PART 3 與 PART 4 的每一張表都標了它對應哪一個檔案。
