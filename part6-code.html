先認識幾個詞

下面每一段都會用到這些詞，先在這裡說一次，之後不再解釋。

  • 下載包：本課給你的那個資料夾（setup_envs.sh、check.py、expected.json、blackjack/，PART 2 第 3 節）。跑完之後它的 blackjack/ 底下會多出三個資料夾：repo/（作者的程式）、logs/（每一步印在終端機上的文字，一步一個檔）、results/（算出來的數字，JSON 格式：一種用大括號和冒號寫資料的文字檔）。out/：本課自己實跑時收下來的那一份 logs 與 results，放在本課網站的程式倉庫（GitHub 上的 marginli/bsc-flyblackjack）的 out/ 資料夾，給想核對的人用；expected.json 裡的標準答案就是從它抄的。不去拿也不影響讀這一頁，本頁寫「本課收在 out/…」只是告訴你每個數字從哪個檔來。
  • 作者：寫 fly-blackjack 這個專案的人，本課重現的對象。repo：放在 GitHub（放程式碼的網站）上的一個程式資料夾；clone：把整個資料夾複製到自己電腦；commit：資料夾在某個時間點的快照，004b2e3 是本課固定的那一個（首頁〈出處〉）。MIT 授權：允許任何人複製、修改、散布，所以本頁可以直接引作者的程式。
  • 環境：一套自成一格的 Python 加套件；conda 是建環境的工具，pip 是往環境裡裝套件的工具。本課只要一個環境，叫 flyplay_bj（PART 2 第 4 節）。
  • 路徑：檔案在電腦裡的位址，像地址。相對路徑：從目前所在資料夾起算的位址；.. 是「上一層資料夾」。作者的程式在 repo/ 裡執行，所以我們的程式寫 ../results/，指的是 blackjack/results/。
  • BJ1 到 BJ5：PART 3 重現作者結果的五步：Dino、切出蕈狀體、制約學習、覓食、21 點；X1 到 X4：PART 4 本課自己加做的四項檢查。代號都是本課編的。
  • 連結體：一顆腦裡每一顆神經元連到哪些神經元、各有幾個突觸（兩顆神經元之間傳訊號的接點）的完整清單；本課用的是雄果蠅的 MaleCNS。把這份清單寫成一張表，第 i 列第 j 欄是「神經元 i 連到神經元 j 幾個突觸」，就叫連結矩陣。蕈狀體：果蠅形成氣味記憶的腦區，模型從連結體切出它的四群神經元：PN（投射神經元，把氣味訊號送進來）、KC（Kenyon 細胞，把每種氣味編成一組「亮」的細胞）、MBON（輸出神經元）、DAN（多巴胺神經元，分 PAM 獎賞群與 PPL1 懲罰群）（PART 1 第 2 節）。
  • 好惡值：模型對眼前這個輸入「想靠近還是想躲」的一個分數，正是想靠近、負是想躲。學習指數：訓練後被懲罰氣味的好惡值掉了多少，減掉另一種氣味的變化，愈負學得愈多。T-maze：讓一群模擬果蠅在兩種氣味之間選邊、數人數的測法（PART 1 第 5 節）。
  • Dino：一個像 Chrome 離線小恐龍的小遊戲，角色一直往前跑、靠跳或蹲躲障礙物。它用的不是蕈狀體，而是作者另外從同一份連結體切出、預先附在 repo 裡的一個 80 顆神經元的小迴路：32 顆收遊戲畫面的輸入神經元、32 顆中間神經元、16 顆下行神經元（從腦往身體送指令的出口，模型從它們讀訊號）。所以本課有兩套電路：Dino 的 80 顆，和蕈狀體的四群（PART 1 第 5 節）。讀出：把神經元的活動翻成動作的那個小網路；CEM：訓練讀出的方法，每一代抽幾十組參數、留最好的幾組、照它們再抽下一代（PART 1 第 5 節）。關卡：Dino 的一局；哪裡出現障礙物由一個種子決定：程式裡的「隨機」其實是從一個起始數字算出來的一串數，那個起始數字叫種子，同一個種子每次得到同一串，所以結果可以逐位相同。
  • 寫死：直接把值寫在程式裡，不能從外面改。匯入（import）：把另一支程式裡寫好的東西接進來，在這支裡直接用。模組：一支可以被匯入的 Python 檔；python -m flybrain.train 讀成「執行 flybrain 這個資料夾裡的 train 這個模組」。

2第一層：兩支 shell script

setup_envs.sh：建一個環境

這支在做什麼。PART 2 第 4 節說過，fly-blackjack 只用三個套件、彼此不衝突，所以一個環境就夠；但套件版本要固定成本課實跑時的版本，對不上時才知道差在哪裡。這支腳本就做這一件事。

  • ①set -e：之後任何一行失敗，整支腳本立刻停。沒有這一行，建環境失敗了腳本還會繼續往下裝套件，錯誤會被埋掉。
  • ②問 conda 它裝在哪裡，存進變數 CONDA_BASE（第 1 節的例子解釋過 $(…)）。
  • ③擋家目錄套件的那個開關；# 後面灰色的字是註解：寫給人看的說明，電腦跳過不執行。
  • ①這兩行定義一個叫 mk 的函式：把「建一個環境」這件事打包，之後叫一次就好。$1、$2 是叫它時給的第一、第二個值（環境名、Python 版本）。三個用 || 接起來的指令讀成「或者」：先看環境在不在（conda env list | grep），在就什麼都不做；不在就 conda create；連 create 都失敗，就加 --solver classic 再試一次。最後那個備案是可攜測試時撞到的（可攜測試：把下載包解到一個空資料夾、從建環境開始從頭跑一次，確認在另一台電腦也跑得完，PART 2 第 1 節）：conda 預設的求解器（決定裝哪些版本的那個零件）在某些安裝裡會壞掉。
  • ②環境建好後，用那個環境自己的 pip 裝套件。${@:3} 是「第三個以後的所有值」，也就是下一行列的套件清單。
  • ①叫 mk 一次：環境名 flyplay_bj、Python 3.11、三個套件各釘在一個版本（==）。numpy 是數字陣列的運算，scipy 這裡只用它的稀疏矩陣（大部分是 0 的表格只存非 0 的格子，連結矩陣就是這種），pandas 讀表格檔。PART 2 第 4 節那張表就是這一行。
  • ②用新環境的 Python 印一行版本號，讓你確認建好了。

6第二層：check.py，驗收

這支在做什麼。run_all.sh 跑完的最後一步。它讀 expected.json（本課實跑的結果，每一項寫著「去哪個檔、取哪個值、用哪種標準比」），逐項去你的 results/ 與 logs/ 取值，比對後印 ✓ 或 ✗，共 19 項。PART 3 第 1 節講的三種判定標準，在這裡變成五種程式判法，本課用到其中三種。

  • ①開頭三個 import：把 Python 內建的三個套件接進來用。json 讀寫 JSON 檔，os 處理路徑，sys 讀指令列給的參數。第 1 到 4 行三個引號夾的是這支程式的說明文字，和註解一樣不執行。
  • ②ROOT：這支程式自己所在的資料夾（下載包的最上層），和 run_all.sh 的 HERE 同一個想法。
  • ③一個字典："blackjack" 這一組對到子資料夾 blackjack。本課原本和另一個重現專題（fruitfly-lab，Doom）合成一門課，這支程式那時同時驗兩個專案，字典是那時留下的形狀；拆成兩門課之後本課只有一組。
  • ①def get(…)：定義一個函式，叫 get，工作是「打開一個檔，沿著一串鍵走進去，取出一個值」。括號裡是它收的四樣東西：檔案路徑、鍵的串列、可選的 pluck 與 mean。
  • ②打開檔案。檔名以 .json 結尾就當 JSON 解析，否則整個當文字讀進來（log 檔走這條）。
  • ③for k in keys：對鍵的串列裡每一個鍵做一次 d = d[k]，也就是一層一層往裡面走。例如 BJ5 那四項寫 ["conditions", "connectome + dopamine", "mean_last"]，就是先進 conditions、再進那個條件、再取 mean_last。
  • ④pluck：遇到「一串東西」時從每一個裡取同一個欄位。本課 19 項沒有一項用到，是拆課前留下的。
  • ⑤mean：把那串數字取平均。BJ3 的三項用它：mb_results.json 裡每個條件存的是 12 個種子的 12 個指數，取平均再比 −1.301。
  • ①讀 expected.json，取出要驗的那一組（which 是 run_all.sh 第 22 行給的 blackjack）。
  • ②結果資料夾：ROOT/blackjack。
  • ③對 expected.json 裡每一項（c）做一次下面的事；ok、bad、known 三個計數器從 0 開始。
  • ④叫上面的 get 取值，存進 got。try 的意思是「試著做，失敗了跳到第 47 行」，檔案不存在也不會讓整支程式當掉，而是記成一項不符。

這段在做什麼。五種判法。if … elif … else 讀成「如果是這種…否則如果是那種…都不是就…」。

  • ①exact：逐位相同，取到的值要和預期一模一樣。本課 19 項裡 17 項用它：BJ3 的三個平均、BJ4 與 BJ4b 的電擊次數與驗證分、BJ5 的四個平均、X1、X2、X4。可以要求逐位相同，是因為 check.py 比的對象是本課的實跑結果，不是作者的數字；而 fly-blackjack 每一步都固定了種子（PART 3 第 1 節）。
  • ②rel：相對誤差。abs(got − v) 是差距的絕對值，不能超過預期值乘上容許比例 tol。本課沒有用到：沒有哪一步沒固定種子。
  • ③same：兩個檔案內容相同。本課沒有用到。
  • ④contains：檔案裡要出現預期的那幾段文字。BJ1 用它：bj1_train.log 裡要出現四列表的四行原文（連同 45、29.12、210.7 這些數字）。
  • ⑤md5_twice：同一支程式跑兩次，兩行 md5 要相同、而且等於預期。BJ2 用它：讀 bj2_md5.txt，split()[0::2] 是把檔案切成一個個字、每隔一個取一個，也就是兩行各自開頭的那串指紋；兩串要相同且等於 32dc4935…。
  • ⑥第 31 行失敗時跳到這裡：記下錯誤的種類，判成不符。
  • ①△ 那一類：expected.json 裡標了 known 的項目，本課實跑時就不符、頁面上已經說明。這一包 19 項沒有一項標 known，所以 PART 2 第 7 節的最後一行只有「通過」與「不符」兩個數。continue 是跳到下一項。
  • ②其他項目印 ✓ 或 ✗；✗ 的後面附上本次的值和預期值，讓你知道差在哪。
  • ③最後一行總結：幾項通過、幾項不符。可攜測試印的是「blackjack：19 項通過，0 項不符（共 19 項）」（out/porttest.json）。第 59 行把不符的數目交回去，第 62、63 行（本頁沒引）用它決定程式的結束碼（程式結束時告訴終端機成功或失敗的一個數：0 是成功、1 是失敗）：有不符就回 1。
